狀態：第一版 Go＋Unity SDK 與獨立示範已建立。本文保留拆分目標；實際組件邊界見 [MODULES.md](../MODULES.md)，通過的檢查見 [第一版驗證紀錄](VALIDATION-2026-10-31.md)。原始遊戲不在這個工作區內修改。

2026-10-31：新增可選的伺服器輸入事件錄製與離線一致性重播，支援逐事件／tick 指紋比對；不是 Unity 畫面播放或完整戰鬥 rollback。操作見 [REPLAY.md](../REPLAY.md)。

## 成果定義

框架提供可重用的伺服器與客戶端能力；Rumblebound 作為使用框架組件組裝的示範遊戲。完成標準不只是搬檔案：框架必須不依賴英雄、武器、據點、地圖資源、遊戲 UI 或遊戲 DTO，並能由不含這些內容的小型範例獨立使用。原遊戲的權威規則與主要流程須通過重組後的回歸驗證。

客戶端有兩種範圍：Go＋Unity SDK 已可輸出 Windows 與 Unity WebGL；另做 JavaScript／TypeScript SDK 才能支援不用 Unity 的純網頁遊戲。兩者共用協定邊界，但不能宣稱 C# 與 JS 的實作只需維護一份。

## 依賴方向

```text
Rumblebound 遊戲／獨立技術選項
        ↓
遊戲協定、移動與戰鬥適配器
        ↓
可選組件：傳輸、恢復、預測、插值、量測
        ↓
核心契約：時間、連線生命週期、訊息、模組能力
```

框架不能反向引用示範遊戲。伺服器與客戶端的模組在建立連線／比賽時組裝，第一版不做戰鬥中任意替換有狀態組件；切換技術選項後於下次連線組裝，重設序號、世代、歷史、緩衝與去重狀態。不同能力分開設定，同一責任的替代策略使用單選 option；相依限制由 UI 與組裝驗證共同執行。

## 現有程式的拆分邊界

| 現有部分 | 通用能力 | 留在遊戲適配器的內容 |
| --- | --- | --- |
| Go gateway transports | 有界訊息、WS／WT framing、寫入取消與關閉 | Origin／身份接納政策、遊戲封包大小設定 |
| Go simulation engine | 固定步長、單一狀態 owner、有界命令佇列、生命週期與量測 | World、英雄、傷害、據點、結算與比賽結束政策 |
| Go gateway connection loop | 單一 writer、逾時、速率限制、控制訊息通道 | 協定內容驗證、ticket／match／generation 授權、loaded／input 操作 |
| C# ClientTransport | 連線 epoch、收送、取消、有界接收、抵達時間 | Rumblebound 的 ProbeMessage／JSON 欄位及遊戲訊息解碼 |
| C# Recovery／ClientSession | 重試政策、身份生命週期 | 遊戲錯誤碼對政策的映射、HTTP 回應 DTO |
| C# MovementView | 可抽取的輸入歷史、預測重播及快照時間軸 | HeroRules、ArenaCollision、攻擊停步、衝刺、存活與復活判斷 |
| SnapshotInterpolation | 快照時間軸、緩衝估計與診斷 | 不應依賴任何角色或彈體型別 |
| FPS／RTT 顯示 | 取樣與診斷資料 | UI Toolkit 樣式、PlayerPrefs 選項與遊戲 HUD |

不把整個 MovementView、Protocol.cs 或 Auth 直接改名為框架；它們目前帶有明確的遊戲規則或範例身份政策。

## 組件加入、停用與移除的驗收

每個可選組件需具備自己的實作、安裝入口、專屬測試、文件及依賴清單。核心僅認識穩定契約與能力 ID。

| 操作 | 預期方式 | 驗證 |
| --- | --- | --- |
| 加入 | 安裝套件並在組裝點選用 | 小型範例及 Rumblebound 都能使用 |
| 停用 | 改一個預設／設定，下次連線生效 | 不再建立或呼叫停用的組件 |
| 替換 | 換成另一個實作相同契約的組件 | 遊戲規則和 HUD 不需改動 |
| 實體移除 | 移除套件與組裝引用 | 核心、必要替代路徑及範例仍可建置 |

沒有安裝但被明確選用的組件，應在組裝時提供清楚診斷；不能用靜默回退讓展示名稱與實際技術不同。已安裝的可選組件也不能因 UI 或建置測試的硬引用而變成必要依賴。

「關閉插值」表示使用最新權威快照呈現；「固定插值」仍會插值，只停用自適應估計。這些模式必須分開命名和測試。角色與彈體共用呈現時間軸；停用後仍須正確處理彈體終點與事件去重。

## 示範方式

技術展示須同時列出選定組件與實際能力。插值、預測、重連、時間、複製、起手、歷史、補償、編碼與範圍分別組裝，量測與弱網分開操作。未實作的完整 rollback 不提供假開關。

比較時固定地圖、英雄、伺服器規則、輸入軌跡與網路到達序列。報告實際呈現延遲、位置修正、停頓、緩衝耗盡與處理成本；不將 RTT 等同畫面端到端延遲，也不以 FPS 一項作為驗收。

## 遷移順序與證據

1. 保存既有成果與回歸基準，建立框架套件和遊戲依賴方向的檢查。
2. 先拆出不含遊戲型別的時間軸／插值組件，完成啟用、替換、停用與移除驗證。
3. 拆出伺服器固定步長／命令執行與傳輸能力，讓 Rumblebound 透過適配器使用。
4. 拆出客戶端傳輸／恢復與預測的通用部分，保留遊戲模擬回呼與規則資料。
5. 以框架重新組裝 Rumblebound，加入獨立技術選項、互斥策略與比較入口。
6. 在沒有 Rumblebound 資源、英雄與協定 DTO 的小型範例驗證重用，並執行至少一個移除可選組件的建置。

每一步都維持可執行的示範遊戲，採同場景比較，不以一次全面搬移取代驗證。框架套件測試須能獨立執行；遊戲另保留私人對戰、練習 AI、碰撞、命中、重連、UI、Windows 與 WebGL 建置檢查。
