# WebGL size optimization (P0)

- The 33 unlit source atlases are archived under `art/b3-production/atlases/<kind>/`. Only the active baked body/shadow atlases remain in Resources. The source images and their original metadata are preserved byte for byte. The Python preparation and review tools and Unity baker use the archive. After regenerating a baked unit's source, run **Tower Duel > Bake fixed-light sprite sheets**, then rebuild. Non-baked definitions still produce a runtime original; the baker archives and removes an identical duplicate when converting.
- Six legacy troop portraits superseded by B3 portraits are preserved in `art/b3-production/legacy-cards/`; Fireball and Frost still use the original fallback folder. The release preflight rejects duplicate portraits and duplicate raw atlases for baked units.
- WebGL uses high-quality automatic GPU texture compression for the animation and environment textures only, preserving atlas dimensions, alpha and Windows settings. Card portraits, UI artwork and fonts are not downscaled or newly compressed. No cache/deploy or protocol changes in P0.
- Build normally with `./examples/tower-duel/scripts/Build.ps1 -Target WebGL`. Inspect `examples/tower-duel/client/Builds/web-build-size.json`: startupTransferBytes is the on-disk sum of the five standard initial WebGL files (not HTTP overhead); files lists actual output file sizes and assets lists Unity packed-asset sizes grouped by source path. These packed sizes are not compressed network sizes. The report is outside the deployed WebGL directory. 
- Verify the resulting size and visual quality on desktop and a real mobile WebGL browser, especially soft shadows, alpha edges, terrain, card portraits and frame slicing. Run the existing B3 baked/lighting review scripts as appropriate. The source moves alone are not a measurement of the final compressed player.
