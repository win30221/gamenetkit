# 雙塔對決｜B3 美術製作與驗收規範 v1.0

狀態：草案，待美術方向確認。本文件只定義製作與驗收標準，不要求立即替換既有素材。

## 1. 美術定位與參考優先順序

統一為「B3 圓潤 Q 版動漫奇幻／賽璐璐上色」。追求手機實際畫面上的辨識度、清晰輪廓與同一款遊戲的整體感，而非單張插畫的精細程度。

1. 以目前遊戲中的盾衛為第一基準，弓箭手、劍士小隊、炸彈兵、突擊兵、攻城兵為同系列參照。
2. 以 [原 B3 風格指南](STYLE_GUIDE_B3.md) 及 [盾衛確認參考圖](references/B3-round-chibi-guard.png) 為補充；正式卡面與正式 Sprite 優先於概念圖。
3. 角色造型、陣營色、職能辨識、腳底錨點與原有遊戲呈現比例不得因美術更新而改變。任何設計變更須先確認。
4. 後四張卡牌目前僅提供角色身份及裝備方向參考，不作畫法或清晰度基準。

正式資源路徑：

- 卡面：`client/Assets/Resources/TowerDuel/B3/Cards/`；兩張既有法術可能由 `TowerDuel/Cards/` 回退載入。
- 戰鬥角色：`client/Assets/Resources/TowerDuel/B3/Units/<kind>/`。
- 角色詳情背景：`client/Assets/Resources/TowerDuel/B3/CharacterStages/`。
- 奇幻 UI：`client/Assets/Resources/TowerDuel/B3/FantasyUI/`。

## 2. 角色繪製共通標準

| 項目 | 必須遵守 | 不接受 |
| --- | --- | --- |
| 人體角色 | 約 2–3 頭身作為起點；大頭、短四肢、圓臉、緊湊體型；以盾衛實際造型校準 | 寫實成人比例、過細的四肢、縮小五官 |
| 動物角色 | 大頭、誇張而簡潔的翼／爪／嘴；保留物種及飛行能力特徵 | 寫實羽毛、密集碎紋理、看不清外輪廓 |
| 外輪廓 | 深海軍藍至近黑，連續、有重量；外線明顯粗於內線；在最終 Sprite 尺寸與盾衛並排校準 | 淺色柔邊、雙重描邊、線條斷裂、邊緣髒污 |
| 上色 | 每種材質約 2–3 個主要色階，硬邊陰影、清楚高光、色塊分明 | 大面積柔焦、厚塗、寫實金屬噪點、過量漸層與反光 |
| 五官 | 簡潔的動漫眼睛、小鼻口、清楚的表情 | 細小且密集的臉部刻畫 |
| 配色 | 職能色鮮明，金色／銀灰／皮革簡化；保留可換陣營色的指定區域 | 所有衣物與特效都被陣營換色、低對比灰濁配色 |
| 光照 | 固定畫面右上亮、左側與下方暗；角色與環境同一光向 | 多光源衝突、黑色死暗、將角色整體畫糊 |
| 裝備 | 武器、盾牌、旗幟、翅膀在縮圖中仍能辨識 | 大量微小裝飾遮蓋角色主輪廓 |

輪廓及造型的判斷以實際顯示尺寸為準，不以生成原圖的放大效果為準。不得用單純放大、銳化濾鏡或描邊後製代替真正重繪。

## 4. 卡牌插畫（Card Art）

### 4.1 尺寸與輸出

- 全套兵種及未來新製法術卡面採 3:4 直式比例；目標高品質母稿至少 768 × 1024 px。
- 新正式卡面以 768 × 1024 px PNG 為目標；既有 384 × 512 px B3 卡面仍為合法基準，不因規範而強制放大或重繪。
- 同一圖不得反覆縮放；從母稿一次裁切／縮小至正式尺寸。不得把低解析度素材插值放大後當成高解析度母稿。
- sRGB；完整背景、無透明邊框、無浮水印、無文字、無稀有度、無費用數字、無卡名、無 UI 框。這些由 Unity 疊加。
- 既有兩張正方形法術卡為相容性例外，未確認前保持原檔；日後重製才採同一 3:4 規格。

### 4.2 構圖與背景

- 優先上半身至大腿的近景英雄構圖，臉與主武器要足夠大。動物及小隊可例外採完整剪影。
- 主體視覺約占卡面 70–90% 高度（目標而非硬切）；重要五官、武器辨識部分不得落在左上費用標誌、下方卡名板或邊框裁切區。
- 每張卡的背景要有獨立設計，依角色職能使用簡潔的放射線、色塊、光帶或幾何圖形；例如盾衛深藍、長槍衛青綠、戰旗手紅金、巡空隼天藍、獅鷲石灰與暖金。
- 背景不可使用高密度城堡、森林、山脈細節與人物搶焦點。卡面背景與詳情舞台是兩類資產。
- 在約 96 × 128 px 卡片（對應目前手機卡組畫面）及更小的對戰預覽上檢查臉、兵器、色彩、剪影。不得僅觀看原圖。

## 5. 戰鬥 Sprite 與動畫

### 5.1 原生素材與有效解析度

- 每一角色先確認高解析度正面／側面／背面造型表，再製作八方向全動作。
- 母稿須保留獨立、未經縮小的方向與動作圖。原始每格有效人物細節應高於最後輸出尺寸，目標主體有效高度至少 256 px；寬翼型角色同時檢查有效寬度。
- 現行 atlas 的 tileSize 可為 192、224、256 px；寬翼或長武器優先選擇能留足邊界的分格。既有 144 px 巡空隼僅作舊版相容，不作新製品質目標。
- 新製人形以約 160–200 px 的 ReferenceHeight 作為目標，與既有盾衛 160 px 對照。寬翼、長兵器與大型角色以完整剪影及實際畫面像素密度共同校準，不可為湊數值裁切角色。
- 不只比較畫布尺寸，必須同時記錄 `tileSize`、`referenceHeight`、實測 alpha 邊界、`worldHeight`、有效像素／世界單位。禁止大量留白後把小角色強行放大。
- 不為提升清晰度改動遊戲世界中的角色尺寸、碰撞、血條位置、攻擊距離或平衡。若調整 tileSize／ReferenceHeight／Baseline，要重新驗證渲染比例與錨點。

### 5.2 Sprite Sheet 格式（保持現有程式相容）

| Clip | 欄數 | 方向列數 | 本體總格數 |
| --- | ---: | ---: | ---: |
| idle.png | 1 | 8 | 8 |
| walk.png | 6 | 8 | 48 |
| attack.png | 6 | 8 | 48 |
| 每套角色合計 | | | 104 |

方向由上至下固定 S、SW、W、NW、N、NE、E、SE。所有動作使用相同分格及腳底錨點設定。原始 atlas 寬 = tileSize × 欄數、高 = tileSize × 8。

正式 `*-baked.png`：上半部八列為固定光向本體，下半部八列為對應的地面陰影；高 = tileSize × 16。最大分格 256 時，烘焙圖高正好 4096 px。不得裁切、改排方向或把相鄰格混進來。

### 5.3 動作與透明背景

- 角色每一方向必須保留相同五官、裝備、手持物、頭身、配色及線條，不得把不對稱裝備直接鏡射。
- 地面單位：待機自然站立；行走六格有完整的踏步、重心轉移；攻擊六格含前搖、命中及收招；實際命中格依 `impactFrame` 和既有權威 tick，通常為索引 3。
- 飛行單位：待機方向一致、walk 為連續振翅循環、attack 呈現明確攻擊動作；不得用地面走路代替。
- 獅鷲地面／空中形態各有完整的 104 格；切換保持造型連貫。地面轉空中不重新設計角色。
- 死亡暫沿用既有共用消散；不要求新增未被程式支援的死亡 atlas。
- 每格透明 RGBA 背景，武器尖端、旗幟及翅膀完整；無棋盤格底、無矩形殘留、無相鄰格殘影、無浮水印、無額外地面圓盤或角色外發光。
- 不得由一張站立圖僅作整體旋轉／縮放來冒充行走或攻擊動畫；每格需有合理的局部姿勢變化。
- 本體色彩與配對地面陰影由既有烘焙流程產生；本體 alpha 必須保持一致。腳底投影固定左下、貼地、柔邊，禁止再疊加重複陰影。

## 6. 卡牌詳情舞台

- 詳情頁展示與戰場相同的正式角色 Sprite（不另畫一個不同風格角色來掩蓋品質問題），地面待機與飛行動作依現有 preview 行為。
- 角色應位於舞台中心，留出武器／翅膀安全區，腳底或空中位置與地面接觸陰影一致；不同角色不強制同一絕對高度。
- 舞台可使用比卡面更有場景感的奇幻插畫，例如庭院、森林、天空、熔火及冰霜；背景對比低於主體，不得直接把角色畫進背景。
- 目標檢查現有約 267 設計單位的舞台，在手機實際像素大小下確認角色沒有被模糊濾鏡、透明黑邊、過度放大或二次縮放破壞。
- 保留石翼獅鷲地面／升空型態切換；同一角色不能因詳情展示而改變正式戰鬥美術。

## 7. UI 與環境美術

- 延續目前奇幻 UI：羊皮紙底、暖金裝飾、深棕輪廓、藍／綠／紅功能按鈕、紫色費用標記。
- 文字和數值一律由 UI 生成；圖片只負責底板、裝飾與圖示。可拉伸邊框及按鈕使用 9-slice，不能拉伸四角、鉚釘或文字。
- 圖示維持相同外框粗細、色階與視覺重量；同一屬性在各頁使用相同圖示。
- 卡牌縮圖在牌組、可加入卡牌、下一張及對戰手牌共用同一正式卡面與比例，不得因顯示位置不同使用低清晰度備份。
- UI 依既有高度基準適配，在不同寬度下調整位置與可見範圍；不得為填滿寬螢幕改變戰場世界比例或把 HUD 拉伸變形。避免頂部 HUD 遮住敵方戰場、底部手牌超出安全區。
- 地圖、城牆、城門、塔與主堡保持現有 B3 圓潤奇幻風、固定光向與規則尺寸。背景以襯托兵種為主；避免高對比碎石、草葉和大量細節搶走人物焦點。
- 不擅自更換已確認的主頁構圖、地圖配置、UI 功能及互動流程。

## 8. Unity 匯入與交付

- 正式卡面與角色 atlas 採無損 PNG、sRGB、NPOT 不縮放、Clamp、Bilinear；預設關閉 mipmap，保持與目前 B3 流程一致。
- 角色使用 alpha 透明；卡面不需 alpha。匯入保持原始尺寸，禁止 Standalone／WebGL 平台覆寫導致 atlas 變形、低於所需尺寸或有損壓縮破壞輪廓。
- 既有程式對 B3 atlas 採未壓縮匯入及尺寸驗證；新素材同時驗證 `DuelSpriteSet.Slice` 和 `TowerDuelSpriteBaker` 相容性。
- 不盲目改用 Point filter：本作是非像素風賽璐璐美術；若需調整取樣必須比較原尺寸、手機縮圖及放大畫面的效果。
- 檢查 WebGL 記憶體與下載量。高解析度母稿獨立於執行時資產；不把所有 atlas 無條件放大到上限，必要時選擇合適 tileSize。
- 每次交付保留角色設計參照、母稿來源、分格配置、提示詞與正式輸出。使用既有檔名與 Unity .meta GUID，避免引用斷裂。
- 不把概念圖、測試拼圖、示意水印或 AI 原始整張多格圖直接當作 Unity 正式 atlas。

## 9. 驗收與防止不同批次畫風漂移

| 關卡 | 驗收內容 |
| --- | --- |
| A. 造型 | 與盾衛／原角色並排比較；頭身、色塊、線條、裝備和角色辨識通過才進入下一步 |
| B. 卡面 | 原稿、96 × 128 縮圖及戰鬥手牌大小比較；3:4、裁切安全、背景不搶主體 |
| C. 動畫 | 八方向逐格檢查，含待機／行走／攻擊；檢查錨點、裁切、動作連續、透明背景及陰影配對 |
| D. 遊戲 | 詳情、卡牌列表、拖曳預覽、紅藍兩方戰場、近遠視角；確認沒有放大模糊、比例漂移或 UI 遮擋 |
| E. 技術 | 正式匯入尺寸、資源引用、WebGL/Windows 建置、既有 Sprite 測試、效能與記憶體；無實測不得標示已通過 |

整套角色不允許只驗一個正面待機畫面。每次製作新角色須同時提交同尺寸比較圖、卡片縮圖、全方向 contact sheet、行走／攻擊循環預覽及實際遊戲截圖。

現有自動驗收可參考 `scripts/Validate-B3-Baked.py`、`scripts/Prepare-B3-Sprites.py`、`TowerDuelSpriteTests.cs`。新增自動檢查時應涵蓋尺寸、透明度、分格、重複幀與裁切；風格品質仍需人工並排確認。像素數、檔案大小或通過結構測試都不能單獨證明美術清晰度。

## 10. 後續製作順序（本草案不執行）

1. 先確認本規範及盾衛基準。
2. 先做長槍衛的正式卡面與正面待機小樣，並與盾衛在相同尺寸比較；確認後才展開八方向及全部動作。
3. 依同一套標準重製巡空隼、石翼獅鷲地面／空中、戰旗手。
4. 後四張共 4 張正式卡面、5 套角色形態、520 格本體（含 40 格待機、240 格移動、240 格攻擊）及對應 520 格烘焙陰影。
5. 逐角色驗收，最後再整體檢視 UI 與戰場。未確認前不批次取代原有美術、不合併 main。

本版定位為後續製作的共同契約；數值屬新製目標，既有素材的相容性例外須保留，若有必要偏離則在角色配置及驗收紀錄說明。
